# Risk Register

| Risk | Probability | Impact | Early Signal | Mitigation |
|---|---|---:|---|---|
| Gameplay feels passive | High | Critical | testers say “I just watch” | behavioral upgrades, faster choices, synergy |
| Art pipeline becomes bottleneck | High | High | days spent on one sprite set | placeholder first, one asset pipeline test |
| Scope explosion | High | Critical | multiple heroes/backends before prototype | milestone gates, backlog discipline |
| AI code debt | High | High | duplicated managers, fragile state | code standards + review prompts |
| Weak onboarding | Medium/High | Critical | drop before first upgrade | start gameplay immediately, funnel analytics |
| Economy becomes grindy | Medium | High | progress stalls early | explicit progression targets + telemetry |
| Monetization hurts retention | Medium | High | shorter sessions after ad rollout | opt-in rewarded, A/B tests |
| Marketability weak | Medium | Critical | creatives fail to communicate fun | test clips before production scale |
| Copycat perception/IP risk | Medium | High | comparisons focus on reference title | original theme, mechanics mix, UI/art |
| Low-end Android performance | Medium | High | frame drops during waves | pooling, VFX budget, device profiling |
| Save corruption | Low/Medium | Critical | lost progress | versioning, backup/atomic write |
| SDK/privacy complexity | Medium | Medium | release blocked by declarations | minimal SDKs, data inventory |
| Content treadmill | Medium | High | retention depends only on new levels | systemic synergies/replayability |
| Build solved too quickly | Medium | High | one dominant upgrade path | tags, tradeoffs, telemetry |
| Backend overengineering | Medium | Medium | no prototype but infra exists | local-first |
