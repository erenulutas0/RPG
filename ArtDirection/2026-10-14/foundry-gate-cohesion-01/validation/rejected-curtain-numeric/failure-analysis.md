# Curtain backing oracle storage correction

The first focused Unity run passed 278 of 279 cases. Only `ActualBayKeepsItsThroatAndExposesARealBackWithoutAFrontOverlay(True)` failed, at the equality between the independently reconstructed visible backing area and the actual backing triangles. The expected area was `0.29114001144611734`; the observed area was `0.29113985198513603`. The equality tolerance was `1e-8`.

The rejected XML and exact test/runtime sources are retained beside this note. `diagnose.py` is a supplemental read-only float32 arithmetic reconstruction, not a replacement for Unity execution. Its `diagnostic.json` reproduces the old expected area exactly and the observed overlap to `2.842170943040401e-14`.

The independent throat geometry was correct. The defect was the rear-polygon oracle's storage boundary: `rear.Add((point.x + inward.x, point.y + inward.y))` widened the scalar sums directly into a double tuple. Those sums could retain precision that the emitted, stored `Vector3` vertices cannot represent. For the far curtain, the first rear Y value was `19.73252010345459` in the old oracle but `19.732521057128906` in stored geometry. The independent domain therefore included a microscopic strip outside the real stored backing and clipped a different strip from its other edge. This is why the overlap error is larger than the difference between the two polygon areas alone.

The repair explicitly stores `Vector3 shifted = point + inward`, then widens `shifted.x` and `shifted.y` into the double tuple. The diagnostic's correctly stored visible domain has area `0.29113992336233707`. This retains the independently reconstructed opening and all double-precision polygon clipping; it only models the same float storage boundary as real mesh vertices. Runtime geometry, the 0.18-unit cavity, and all source coordinates remain unchanged. Neither the `1e-8` backing equality nor the `1e-8` visible-overpaint bound was relaxed.

The root reran the focused Unity suite after this test-only correction: **279/279 passed**, recorded in `../focused-editmode.xml`. Root also confirmed isolated compilation with zero warnings and zero errors. The source was frozen before the fresh After capture. This result establishes the repaired numerical oracle and focused regressions; full suites, final graphics/resource acceptance, APK and device validation remain separate gates.
