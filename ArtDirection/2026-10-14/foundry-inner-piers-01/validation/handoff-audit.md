# Handoff draft audit

Read-only review of `TestResults/claude-visual-handoff-draft.md` against current source and the latest accepted records, 2026-10-14. This audit does not accept the pending inner-pier candidate or replace its final validation. No Assets were edited and no Unity or device operation was run.

Material corrections for finalization:

1. **Document the new family finish explicitly in sections 5 and 9.** The gate map still lists only the older shared helpers. Current `FoundryRegionGateInnerPiers.cs` owns `BuildGateInnerPier`; `FoundryRegionGatePierFinish.cs` owns `GateInnerPierGrain` at **.11** density and `AppendGateStone`. `GateHouseGrain` stays **.075** for the header, inner returns and cartouche. `BuildGateArchitecture` finishes those pieces separately, then appends them in header / pier / return / pier / return / cartouche order. A final `GateHouseGrain` over the merged builder would erase the family treatment and change subdivision cost. Preserve this boundary when the candidate is finalized; do not describe .075 as the finish of every native gate face.

2. **Extend the source-freeze rule beyond runtime files.** Section 6 currently says runtime changes supersede evidence. The freeze covers the Assets test sources and metadata too. This package's initial focused run was superseded after a test-fixture correction, despite unchanged runtime. Say that any change to the recorded frozen Assets invalidates the matching freeze claim and requires the lead to regenerate the affected compile/test/capture evidence. Do not carry a passed XML forward merely because only a test changed.

3. **Do not present the existing package capture command as a reusable next-task command.** `Run-FoundryInnerPiersProof.ps1 -Phase after` writes to the fixed `foundry-inner-piers-01/after` directory; `FoundryInnerPiersCapture.cs` hardcodes that output. Once this package is accepted, rerunning it on a new candidate would overwrite the accepted After images. Label the command as reproduction/current-package-only. A subsequent art package needs a new output directory and launcher pinned to its own baseline, with accepted proof preserved.

4. **Add the already implemented swarm and ground-reward boundary to the product summary.** The six-room Descent description is valid but incomplete in a way that can misdirect a later gameplay handoff: the final swarm, clock-driven ladder, upgrade sittings, walked exit and visible XP/gold pickups already exist. `Docs/21` S6c/S6d and the subsequent ground-drop/exit presentation closures supersede the older GDD statement that continuous combat is merely a fallback. Source includes `SwarmDirector`, `SwarmRule`, `GroundDrops`, `GroundDropView` and `ExitSealView`. Ground rewards apply outside the swarm; the live pickup radius is 1.0. Keep the distinct **regional branching route/gate travel** deferred, but do not suggest implementing the final swarm or ground drops from scratch as wider product work.

The lead already identified the separate coin-identity wording correction; it is not duplicated here. The conditional next workyard-family proposal agrees with the latest accepted priorities. No additional material correction was found in the stated map bounds, active bake/fallback distinction, budgets, device boundary or crowd limitation.
